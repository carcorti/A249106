## Required checks and precise scope

The bounded command `python3 validation/run.py` verifies the complete package
inventory, citation metadata and all archive provenance entries. It recomputes
seven positive chains (28 operand factorizations), runs the historical sixth/
seventh and eight-prime validators in normal and optimized Python, verifies
the complete phase records with the original binary, and reconciles seven
adjacent segments, 9,565,674,609 inputs, two hits and the 7983.66-second timing
sum. It also builds C afresh and checks seven singletons, three independent
SymPy windows (499,31,31 inputs), one/four/eight-thread equality on two
16384-input windows, segment grouping, corrupt-digest rejection and forced
fallback/wide-root paths. It leaves the package bytes unchanged.

The canonical b-file has exactly seven rows, contiguous indices 1 through 7,
and the accepted historical five-row common prefix. The b-file, indexed
witnesses and prime-family table end with exactly one empty terminal record
(two LF bytes). The prime-family parameter is not an OEIS index. No auxiliary
sparse a-file is supplied: later family members have no assigned indices.

Optional bounded operational and sanitizer replays are described in
`notes.md`. Their original evidence and source identities are retained in
the archives. Broad earlier-build tests transfer only to byte-identical
source regions; final-build initialization and I/O checks have their own
records. None supplies full-campaign sanitizer coverage or an independent
rescan of negative intervals.

A release preflight checks all identity, CFF, license, README-math, DOI-scope,
PDF/TeX, data, provenance and checksum obligations on the final frozen bytes.
It rebuilds the PDF to settled references and checks the final log, embedded
metadata, links and every rendered page. Clone-like and independently
extracted GitHub/Zenodo-shaped archives include all dotfiles and must run the
documented public commands from unrelated root names. Missing, altered and
unexpected-file controls must fail closed for their intended reasons.
The invocation-specific logs and verdict are retained outside the package;
local simulation is not actual-provider verification. Only fresh checks of
both actual provider payloads after publication support DISTRIBUTED RELEASE PASS.
